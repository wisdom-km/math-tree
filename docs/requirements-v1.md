# math-tree 需求文档 v1

> 人教版小学数学知识树教学系统。第一阶段只做六年级上册及其直接依赖的旧知识。
> 状态：讨论定稿，待 Wisdom 审。本文档是后续所有设计与实现的依据；改需求先改这里。

## 1. 一句话定位

一棵跨年级的数学知识树，树上挂着可视化探究单和三种卡片（主卡 / 副卡 / 方法卡），每个孩子在这棵树上有自己的掌握度着色。老师用它上课、诊断、定向补弱；孩子用它动手探究、背记、练母题；家长看报告。

## 2. 用户与场景

| 角色 | 场景 | 第一版范围 |
| --- | --- | --- |
| 老师 | 在智慧大屏（Chromium 内核一体机）上投屏上课；课后录入掌握度；查看全班与个人弱点；导出家长报告 | 完整 |
| 学生 | 直接在大屏上触摸操作探究单；看自己的知识树着色和弱点 | 完整（大屏共用，无个人设备） |
| 家长 | 收老师导出的 PDF 报告 | 只收 PDF，不登录系统 |

课堂模式：**投屏模式**。老师一台电脑，投到触摸大屏，孩子上台操作。"猜一猜"环节全班举手，老师在屏上快速记录候选值的举手人数形成分布图。
人手一台模式（每个学生自己的设备 + 教师端实时汇总）为第二阶段，见第 10 节。

## 3. 核心模型：知识树

### 3.1 节点类型

| 节点 | 说明 | 对应产物 |
| --- | --- | --- |
| 知识点 | 定义、公式、定理，教材中的一个最小教学单位 | 主卡 |
| 母题 | 一类题的"根"，其他题都是它的变形 | 副卡 |
| 方法 | 解题工具，跨单元复用（画线段图、找单位"1"、转化……） | 方法卡 |
| 探究单 | 一个可视化交互，挂在知识点或关系上 | 可视化程序 |
| 课 | 把上面几种节点按课前 / 课中 / 课后组织起来的教学单位 | 课的页面 |

### 3.2 关系类型（边）

| 关系 | 含义 | 例子 | 用途 |
| --- | --- | --- | --- |
| 转化自 | 新知识由旧知识推导而来 | 圆面积 → 长方形面积 | 往前回溯；沿链播放；诊断时找前置薄弱点 |
| 拆解为 | 拆到孩子已经会的最小要素（第一性原理） | 圆面积 → 面积的意义 → 圆数不了格子 → 转化 → 份数越多越接近 | 主卡"拆解"栏；副卡"考点"栏 |
| 联系 | 平行的互通关系 | 比 ↔ 除法 ↔ 分数 | 主卡"联系"栏；联动可视化 |
| 易混 | 容易混淆的两个知识点，差在哪 | 周长 vs 面积；平均分 vs 包含除 | 主卡"对比"栏；并排可视化；副卡"常见错法" |
| 考察 | 母题在考哪个知识点 | 求圆环面积 → 圆面积、面积的加减 | 出题人视角；AI 批改对齐 |
| 使用 | 母题用哪个方法解 | 分数除法应用题 → 找单位"1"、画线段图 | 方法卡"例题"；副卡"方法"栏 |

### 3.3 年级范围原则

教哪个年级的内容，就只建该年级的节点 + 它**直接依赖**的旧知识节点。
第一阶段：六上全部知识点 + 六上直接依赖的五年级及以前节点（估计 20–30 个）。旧知识节点只做主卡 + 一个迷你回忆探究单，不做母题。
树的结构对年级无关；以后上传五上、五下的教辅，是在树上加节点，不改结构。

### 3.4 掌握度

每个学生 × 每个知识点一个等级：

| 等级 | 含义 | 典型来源 |
| --- | --- | --- |
| 没学 | 未接触 | 默认 |
| 听过 | 上过课，能复述定义 | 老师录入 |
| 会做 | 母题及变式能独立做对 | 母题练习记录、AI 批改建议 + 老师确认 |
| 会讲 | 能用费曼法讲给别人听 | 费曼自测，老师打勾 |

回溯诊断：某六上知识点标为薄弱，系统沿"转化自"边列出前置知识点，老师逐个核查，薄弱的继续往前。**第一版不做自动测评算法**，是老师录入、系统按树推荐检查顺序。

## 4. 功能模块

### 4.1 可视化探究单

**交互三层**，目标是每个知识点尽量做到第三层：

- L1 演示：老师点播放，动画自己动。
- L2 操作：孩子调参数，画面跟着变。
- L3 探究：有任务、有猜想、有数据、要自己归纳。程序不直接给公式，公式是孩子填出来的。

**探究单固定骨架（10 步）**：

0. 回忆：先操作一个旧知识的迷你可视化，把旧知识"叫醒"（1 分钟）。
1. 情境：一个真问题，不带数学词，少文字。
2. 先猜：孩子给出"太高 / 太低 / 最可能"三个估值，才能进入操作。投屏模式下全班举手记录分布。
3. 动手：拖、调、滚。参数由孩子控制。启动时画面不动，只有一个抖动提示指向可拖的东西（PhET 的 wiggle-me）。
4. 数据自动记录：一键"加入数据表"，每试一次多一行。
5. 找规律：程序留空让孩子填。句式开头："我发现 ______，因为 ______"。
6. 揭示 + 命名：填完才出现公式和术语，并连接数学史（割圆术、祖冲之）。
7. 反向验证：用刚发现的规律预测新情况，再操作验证；回到第 2 步对照谁猜得最准。
8. 老师提问卡：屏幕角落一个不显眼的按钮，每屏预置 2–3 条苏格拉底式问题。学生模式隐藏。
9. 延伸："这个以后还会用到……"，埋钩子（如圆面积 → 六下圆柱体积）。续集挑战可选。

**设计约束**：

- 约束式沙盒：每课只开放 1–2 个核心参数可拖，其余锁定；参数范围限制在有教学价值的区间。
- 活公式：一个探究单只有一份数据（单一数据源），图形、数值、表格、公式全绑在它上面。公式里的数字实时替换并高亮，如 C = 2 × π × **5** = **31.4**。
- 易混并排：易混关系做成同屏并排可视化，一个参数变，两边同步变。如同一个圆调半径，左边周长变长、右边面积变大，公式同步。
- 界面一致性传递联想：同一条转化链上的探究单用完全相同的界面（同样的网格、颜色、"剪 / 移 / 拼"三个按钮），孩子自己会说"又是这招"。
- 图形全部代码绘制（SVG），参数驱动，不用图片。

**不能可视化的内容**：做成图解式的静态页（类似 PPT 的分步展示），或直接只有主卡。不强行可视化。

**大屏触摸硬要求**：按钮和拖点不小于 48px；无悬停、无物理键盘依赖，数字输入用屏幕大数字键盘；支持多点触控，允许两个孩子同时各拖一个点；字号以 3 米外可读为准；Chromium 内核一体机（希沃等）为目标环境。

### 4.2 主卡（知识点卡）

定位：背记用。经典、短，不给孩子加负担，不是重新上课。理解性内容也写成可背的陈述句。正面不超过 50 字。

模板：

1. 名称
2. 一句话定义
3. 文字语言 / 符号语言 / 图形语言（图形语言 = 对应探究单的缩略图）
4. 拆解要素（如百分数：一个数 / 另一个数 / 百分之几 / 倍数关系）
5. 怎么记（记忆法、口诀）
6. 联系（往前：来自哪个旧知识，沿"转化自"边自动生成）
7. 对比（横向：和谁易混、差在哪，沿"易混"边自动生成）
8. 费曼自测：一句话，"你能给同学讲清楚……吗？"

### 4.3 副卡（母题卡）

定位：题量少，每题练到透。目标是孩子看到题能**识别**该用什么方法，而不是刷题。

模板：

1. 题干
2. 考点（指向知识点节点，即出题人在考什么）
3. 识别信号（看到什么特征就知道是这类题）
4. 用什么方法（指向方法卡）
5. 解题步骤（结构化，每步对应一个要素；这也是 AI 批改对齐的依据）
6. 出题人怎么变（改哪个要素、改问法、加条件）
7. 常见错法（指向易混边）

两个层级：

- 单元母题：只考本单元。
- 综合母题：学完若干单元后，一题串多个知识点（圆 + 三角形 + 百分数 + 乘除法）。

### 4.4 方法卡

独立的第三种卡。一个方法跨多个单元，独立后孩子能看到"画线段图在分数乘法、分数除法、比里都用得上"。

模板：名称 → 什么时候用（识别信号）→ 怎么做（步骤）→ 适用于哪些知识点 → 例题（指向母题）。

六上方法初步清单（待对照教辅校对）：画线段图、找单位"1"、转化（图形 / 数）、数形结合、假设法、列表找规律、逆推、方程法、按比分配套路、百分数三类题模板。约 10–12 个。

### 4.5 课

一个知识点配一节课。课是三种卡和探究单的组织主轴：

- 课前：回忆卡 1–2 张（旧知识主卡 + 迷你回忆探究单）。
- 课中：探究单 1 个 + 老师提问卡。
- 课后：主卡 1–3 张背记 + 母题 1–2 道。

### 4.6 名册与掌握度录入

- 名册：老师建学生（只有名字），无密码、无学生登录。点小 A 看小 A 的树着色、进度、难点；点小 B 看小 B 的。
- 录入方式：
  - 老师手动改等级。
  - 母题练习记录：孩子在系统里做母题的结果。
  - 费曼自测：老师打勾。
  - AI 批改：拍照上传孩子手写作业，AI 识别并分析错在哪一步、对应哪个知识点，**给出建议**；老师确认后才改掌握度。AI 不直接改数据。
- 隐私：投屏时有"只看当前学生"模式，不暴露其他孩子的数据；作业照片只在分析时上传，不长期存云端；家长知情。

### 4.7 报告

同一份数据三个视图：

- 老师：全班热力图（知识点 × 学生）、单个学生的树着色 + 弱点回溯链。
- 家长：一键导出 PDF，含树着色图、弱点清单、建议。
- 学生：在大屏上看自己的树着色和弱点（"只看当前学生"模式）。

## 5. 内容规范

- **内容与代码分离**：知识树、三种卡、探究单文案全部用结构化文件（Markdown + YAML 元数据）存放；代码只负责渲染。上传五上教辅后生成的是新内容文件，不改程序。
- **来源与审核**：由 AI 助手起草 → 对照 Wisdom 提供的教辅 PDF 校对术语与顺序 → Wisdom 审 → 标注"已审"。未审内容不进课堂。
- **经典优先**：以教材原文、教参表述为准；不自创术语。
- **教辅 PDF 只作参照**，不进仓库（版权）。仓库内只有我们自己写的内容。

## 6. 技术方案

- 前端：React + TypeScript + Vite。
- 渲染：SVG 为主，参数驱动；几何计算用 `@mathigon/euclid`（MIT）；构造几何多的课可用 JSXGraph（MIT / LGPL）。
- 状态：每个探究单单一数据源，所有视图派生（活公式的基础）。
- 数据层：**第一版就用 SQLite**。架构为"本地小服务端 + 浏览器前端"：老师电脑上运行一个 Node 进程（Fastify 或 Hono），用 better-sqlite3 读写一个 `.db` 文件（名册、掌握度、练习记录、AI 批改建议），同时托管前端静态页；浏览器打开 `localhost` 使用，投屏到大屏。ORM 用 Drizzle（schema 用 TypeScript 写、自带迁移，同一套 schema 可切到 Postgres / MySQL），第二阶段把这个服务端搬到云上即为多端同步的后端，业务代码不动。
- 数据文件即备份：`.db` 单文件可复制、可随老师电脑迁移；提供"导出 / 导入数据"按钮。
- 不选浏览器 IndexedDB 或 WASM 版 SQLite 的原因：数据存在浏览器沙箱里，清缓存即丢，也不方便备份和迁移。
- 打包（可选，M2 后评估）：用 Tauri 把服务端 + 前端打成桌面安装包，老师双击启动，不用装 Node。
- 导出：PDF（家长报告、卡片打印）。
- AI 接入：多引擎 + 用户自带 API Key（复用沉浸译的引擎配置思路）；用多模态模型做手写识别与错因分析；输出结构化结果（母题 id、出错步骤、对应知识点 id）。
- 不以 GeoGebra、网络画板、Polypad 为底座（商业授权 / 请求额度问题），它们只作原型对照。
- 揭示环节的讲解动画可用 Manim 离线渲染短视频嵌入（可选）。
- 第二阶段实时同步：WebSocket（Socket.IO 或 Yjs），学生凭课堂码免登录。

## 7. 六上内容地图（初稿，待对照教辅）

| 单元 | 可视化候选 | 直接依赖的旧知识 |
| --- | --- | --- |
| 分数乘法 | 折纸面积模型（先横折涂色再竖折，数重叠格子）；数轴上的"几分之几的几分之几" | 整数乘法意义（几个几）、分数的意义、分数加减法 |
| 位置与方向（二） | 寻宝游戏：拖角度和距离找宝藏；台风路径动画 | 八个方向、角的度量 |
| 分数除法 | 量杯倒水：包含除 vs 平均分两种意义分开演示；倒数 | 除法两种意义、分数乘法 |
| 比 | 调颜色：红蓝按比例混色，发现 2:3 与 4:6 一样；按比分配拖分界点；比 / 除法 / 分数三角联动 | 除法、分数、商不变性质 |
| 圆 | 轮胎滚动量周长 + 数据表发现 π；割圆术；圆面积切拼成长方形 / 拆成三角形；周长 vs 面积并排 | 长方形面积、平行四边形 / 三角形 / 梯形面积、周长概念、正方形周长 |
| 百分数（一） | 百格图涂色；折扣滑块；分数 / 小数 / 百分数三者互换 | 分数、小数 |
| 扇形统计图 | 拖扇区边界，条形图与百分数同步；反例：饼图看不出总量 | 条形统计图、折线统计图、扇形 |
| 数与形 | 正方形点阵一层层加 L 形，1+3+5+7 = 4²；正方形不断切一半涂色，1/2+1/4+1/8+… 逼近 1 | 平方数、分数加法 |

图形面积转化链（"转化"是主线，五上四个图形做出来当回忆）：
长方形（数格子）→ 平行四边形（切移拼）→ 三角形（两个拼成平行四边形，÷2）→ 梯形（两个拼成平行四边形）→ 圆（切成扇形拼长方形；或拆成 n 个三角形，½ × C × r = πr²）。五个探究单共用同一界面。

## 8. 里程碑

- **M1**：项目骨架（前端 + 本地服务端 + SQLite schema 与迁移）；知识树骨架（六上 + 直接依赖旧节点，内容文件格式定稿）；圆的周长探究单；圆的面积探究单；图形面积链（含五上四个图形回忆）；树的浏览界面。
- **M2**：圆单元的主卡、副卡、方法卡全套；课的页面；名册 + 掌握度手动录入（落 SQLite）；家长 PDF 导出。用一个单元验证整套模型。
- **M3**：其余七个单元逐个铺内容；AI 批改（建议 + 老师确认）。
- **M4**：人手一台模式 + 服务端上云 + 实时同步。

## 9. 第一版明确不做

学生账号（只做名册）、自动组卷、题库、AI 直接讲题、在线同步、四五年级完整内容、自动测评算法。
